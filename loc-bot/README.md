# Loc Bot

Набросок бота локализации для Band (Mattermost) и WB Tracker. Делает то же, что кнопка «→ Tracker» в расширении
Loc Helper, но командами в треде — и работает для всех, без установки расширения.

Бот ничего не делает сам: менеджер пишет команду в треде с брифом, бот показывает превью
и создаёт задачу только после подтверждения.

## Команды (пишутся в треде с брифом)

| Команда | Что делает |
| --- | --- |
| `!задача` | Показывает превью: название, тип, исполнитель, языки, дедлайн, поля Tracker, чего нет в брифе. Ничего не создаёт |
| `!создай` | Создаёт задачу по превью |
| `!создай подзадачи` | Задача и подзадача на каждый язык |
| `!создай подзадачи редактура` | Подзадачи отдельно на перевод и на редактуру |
| `!создай в LOCAL-123` | Создаёт подзадачей в указанном тикете |
| `!комментарий в LOCAL-123` | Добавляет бриф комментарием в существующий тикет |
| `!отмена` | Отменяет превью |

К `!создай` можно дописать поправки: `тип=Перевод`, `заказчик=WBP Чаты`, `срок=25.12`.
Исполнителем становится тот, кто дал команду (ищется в Tracker по логину из Band).
Команды слушаются только от людей из списка `managers`.

Если задать `reactionTrigger` (имя эмодзи, например `ticket`), реакция менеджера на бриф работает как `!задача`.

## Запуск

Нужен Node.js 22 или новее. Сторонних пакетов нет, `npm install` не нужен.

1. Положите рядом две папки из репозитория: `loc-bot` и `loc-helper` (бот берёт из неё `lib/brief.js` и `lib/core.js`).
2. Скопируйте `config.example.json` в `config.json` и заполните.
3. Запустите: `node bot.js`. В консоли должно появиться «Band: вошёл как …», «Tracker: …», «Band: слушаю события».
4. Добавьте бота в канал с брифами и напишите в любом треде `!помощь`.

Бот работает, пока запущен. Для пилота его можно держать на своём компьютере; для постоянной работы нужен сервер
во внутренней сети, откуда доступны Band и Tracker.

## Настройки (`config.json`)

- `bandToken` — токен бота из Band. Можно и личный токен: тогда бот пишет от вашего имени.
- `trackerToken`, `trackerLogin` — API-токен Tracker и логин его владельца. Автором задач будет этот пользователь.
- `sampleIssue` — номер любой задачи проекта: по ней бот узнаёт пространство, проект, типы задач и поля.
- `issueUrl` — как выглядит ссылка на задачу, `{code}` заменяется на номер. Проверьте, что ссылка открывается.
- `managers` — логины в Band, чьи команды бот выполняет. Пустой список — бот никого не слушает.
- `channels` — названия или id каналов, где бот работает. Пустой список — во всех, куда его добавили.
- `prefix` — с чего начинается команда (по умолчанию `!`).
- `defaultType` — тип задачи в превью.
- `reminders` — напоминания о дедлайнах личным сообщением исполнителю за `hoursBefore` часов.
  Приходят только тем, кто перечислен в `users` (логины). По умолчанию выключены.

`config.json` и `state.json` в репозиторий не попадают: в первом лежат токены.

## Ограничения

- Это набросок: логика проверена на макетах Band и Tracker, на настоящих сервисах бот не запускался.
- Кнопок в сообщениях нет, только команды. Кнопкам нужен адрес, по которому Band может обратиться к боту, то есть сервер.
- Превью живёт в памяти: после перезапуска бота нужно снова написать `!задача`.
- Вложения из треда в задачу не копируются, в описании остаётся ссылка на тред.

## Файлы

- `bot.js` — весь бот: подключение к Band, команды, превью, создание, напоминания.
- `config.example.json` — образец настроек.
- `../loc-helper/lib/brief.js`, `../loc-helper/lib/core.js` — разбор брифа и работа с API Tracker, общие с расширением.
